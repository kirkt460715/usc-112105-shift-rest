# 联合班务核算

虚构的多点位轮班协议，点位使用 America/New_York，其记录包含秋季时钟回拨。区间包含起点、不含终点。

项目使用 Python 3.11.2 标准库。资料按来源表以 UTF-8 JSON Lines 保存，每行是一条记录。缺失值写作 `null`，其业务含义见资料约定。列名见 `data/manifest.json`，编号由各资料表原样保留。

[资料约定](docs/materials.md)说明各表的来源、时间及关联语义。

## 快速开始

```sh
python3 inspect_inputs.py                 # 只读资料，确认可读
python3 -m unittest discover -s tests -v  # 单元测试
python3 selfcheck.py                      # 关键不变量自检
```

## 命令

```sh
python3 -m roster review                  # 月度复核（欠休、分组、补休积欠、签到缺失）
python3 -m roster review --json out.json  # 另存机器可读结果
python3 -m roster coverage                # 岗位覆盖与个人工时去重
python3 -m roster decisions --person U6   # 解释某人的属地工作日与观察窗判定
python3 -m roster plans                   # 四套候选班表试算与比较
python3 -m roster plans --detail          # 逐套明细
python3 -m roster trial my_plan.json      # 试算自定义方案
python3 -m roster confirm --plan D-补休兑现 --state state   # 管理员确认
python3 -m roster status --state state    # 回看已确认方案与旧账
```

## 口径

### 时间

所有记录先折成 UTC 瞬时再比较。带偏移量的签到按偏移量记录的**真实经过时间**计算：
`01:10-04:00` 到 `01:45-05:00` 是 95 分钟，不是墙上时间的 35 分钟。不带偏移量的时间
按职工所属时区的墙上时间解释；回拨当日的歧义时刻取第一次出现。属地工作日按点位日历日
呈现，回拨日为 25 小时。

### 在岗义务与个人工时

证据分四层，互不替代：

| 来源 | 含义 | 用途 |
| --- | --- | --- |
| `duties` | 签定义务 | 观察窗起点、按义务推定的口径 |
| `clock` | 实际签到 | `onsite` 计在岗，`standby` 计等候指令 |
| `loans` | 借调 | `confirmed` 定位到新岗；`conflict` 只确定“人在工作” |
| `breaks` | 休息确认 | `free` 可自由支配；`recall` 到召回时刻为止；`standby` 不算休息 |

个人工时按人合并：同一人同一时刻在两个点报在岗，只计一次。岗位覆盖另算，要求该点上
有人且这一刻没有别处占用他；已确认借调期间原岗不再自动计为覆盖。

等候指令计入个人义务工时，但不构成岗位现场覆盖，也不算自由休息。

### 连续休息：三档口径

每个观察窗同时计算三个值，互相不能替代：

- **下界**：只用有证据的自由休息，扣掉与之冲突的已确认/争议借调；
- **上界**：无记录时间按可能休息计，已记录的等候与借调不算休息；
- **按义务推定**：按签定义务在岗计算，签到缺失不会凭空多出休息。

由此得出三类结论：

- **已确认欠休**：上界也不足。生成工单，可安排补休。
- **还可能欠休**：上界够、下界不够，且观察覆盖达标。只列调查，不生成承诺。
- **观察不足**：上界够、下界不够，但窗内义务的观察覆盖低于协议下限。不能判为满足，
  也不能生成补休。

签到缺失单独列出，**不按休息计**。因此缺观察的组不会因为“没记录”而显得更安全；
分组比较同时给出下界、上界、按义务推定三个平均值，排序不一致时会明确指出。

### 工单与合并

同一人、同 `dedup_group` 且相交的不足范围只出一张工单，补休取触发条款的最高值，
避免同一时段重复承诺。已签收的补休先占用当事职工，不再参与新班次排班，
并在工单上显示尚欠分钟数。

### 候选班表

四套方案平行试算：

| 方案 | 做法 |
| --- | --- |
| A 不排休息 | 只排人，暴露班内无休息的后果 |
| B 只排有替班的休息 | 没有合格替班就不排，保留真实缺口而不虚构覆盖 |
| C 借调补位 | 用候选名单外的人补位并排休，替班占用会截断替班人自己的休息 |
| D 补休兑现 | 在 C 基础上兑现旧欠休，按人错开时段，不重复兑现 |

每套都报告：必守岗位失去覆盖的班次、未达连续休息的人次与分钟、缺口归因
（替班造成 / 本人被连排）、可避免与不可避免的欠休、兑现与仍欠的补休。
平均休息上升时，报告仍逐人列出违规者，不会用均值掩盖个体底线。

### 确认与留痕

`confirm` 写入 `state/confirmed_plan.json`，包含方案定义、兑现时段（含原班次与条款）、
仍待调查的观察不足、仍未安排的旧欠账、以及旧班表的已签收承诺及其对应工单。
再次确认时会记下上一版方案与仍未结清的项目，旧承诺可随时用 `status` 查回。
